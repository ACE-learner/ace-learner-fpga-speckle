# Skill 技能包（可复用于其他 FPGA 视觉加速题）

> 本目录把"与大模型协作过程中沉淀下来的经验"显式整理成可复用的技能，
> 每项都写明**适用范围、使用方法、已验证效果、失效条件、来源（哪次失败总结出来的）**。
> 目标：一支陌生队伍拿到本目录，可以直接套用到自己的 FPGA 加速题上。

## 使用方法（推荐顺序）

1. **开题/划分阶段**：用 `prompt_workflows.md` 的 ①软硬件划分模板，让大模型帮你列出哪部分跑 PL、哪部分跑 PS，并要求给出"依据 + 风险"。
2. **上板阶段**：按 `case_templates.md` 的 bring-up 清单逐项检查；用串口抓取模板建立日志。
3. **卡住时**：先查 `pitfalls.md` 是否命中（现象→根因→排查步骤），仍无法定位再用 ③④ 提示词。
4. **验收阶段**：跑 `validation/check_package.py` 自检；按五层验证法出对照表。
5. **提交阶段**：用 ⑤ 提示词做"打包完整性 + 复现步骤"自查。

## 已沉淀的关键经验（一句话版）

- 板端"能跑"≠"跑对"：必须用 **PC 参考结果** 对齐（本工程板端与 PC 关键点 96.7% ≤2px）。
- **C 标准库 `fopen` 在 Zynq BSP 里读不了 SD 卡**，必须用 FatFS `f_open`（最隐蔽的坑）。
- 串口日志要**先清缓冲、等本次运行标记**，否则会把上次残留当成新结果。
- 权重/输入/解码口径三者任一不一致，都会导致"精度突然变差"的错觉；先核对**哈希 + 形状 + 解码参数**。
- 断电重启跑两遍对比，是判断"时序/状态相关随机错误"的最低成本手段。

# 04 性能测量与结果可信度（Bench & Trust）

## 适用范围
所有需要在报告里给出"板端延迟/吞吐"的题目。与算法无关，核心是避免把"编译/首次加载/异常帧"算进稳态。

## 使用方法

### 步骤 1：用模板测量
```bash
python bench_template.py --bit my.bit --ip my_accel_0 --warmup 5 --repeat 50 --csv bench.csv
```
- `--warmup`：前 N 次不计入（首次调用含加载/编译/缓存预热）；
- `--repeat`：正式测量次数；
- 输出：p50/p90/p99 延迟、吞吐、CSV 原始数据。

脚本内置两种计时基准：
- `perf_counter`：Python 侧端到端（含 Python 开销，适合"用户看到的延迟"）；
- 若 overlay 内 IP 带硬件周期计数器，可改用寄存器读数（README 给出方法）。

### 步骤 2：结果可信度自查清单
1. 是否预热？首次调用通常慢 2~10 倍；
2. 是否包含数据传输？PS↔PL 的 DMA/拷贝如果是流水线一部分，必须计入端到端；
3. 是否同一输入重复测？不同输入的耗时可能差很多；
4. 是否取了分位数而不只是平均？偶发卡顿会污染平均值；
5. 是否记录了时钟频率/电压/温度？这些会显著影响结果；
6. 是否分开报"纯计算"与"端到端"两个数？报告里都写清楚。

### 步骤 3：无板子时
```bash
python bench_template.py --mock
```
用模拟函数验证预热/分位数/CSV 逻辑（本包已实测）。

## 已验证效果
- 离线（PC）：mock 模式输出 p50/p90/p99 与 CSV，逻辑正确（本包已实测）。
- 上板：把 `--csv` 得到的原始数据直接作为报告附件；README 中填"实测 p50、p99 与测试条件"。

## 失效条件
- 只测 1~2 次：分位数无意义；
- 把 Jupyter 交互延迟当板端延迟：需在板端脚本内计时；
- PL 时钟变化后未重测：所有性能数据都会变。
